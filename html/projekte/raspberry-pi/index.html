PROJEKT 01 · RASPBERRY PI

Mein eigener Webserver.

Diese Website läuft nicht auf einem klassischen Webhosting- Paket, sondern auf einem Raspberry Pi bei mir zu Hause. Von der Hardware über Docker und Nginx bis zur sicheren Verbindung ins Internet habe ich die komplette Infrastruktur selbst aufgebaut. Inzwischen wird der Server überwacht, rollt Änderungen selbst aus, ist vollständig als Code beschrieben und sichert sich mit getesteten Backups.

ARCHITEKTUR

Vom Raspberry Pi ins Internet.

Der Raspberry Pi ist nicht direkt aus dem Internet erreichbar. Stattdessen stellt Cloudflare einen Tunnel zum lokalen Webserver her. Für Web-Dienste ist kein einziger Port geöffnet, Admin-Oberflächen erreiche ich nur per SSH-Tunnel.

MONITORING

Probleme erfahren, bevor Besucher sie merken.

Der Monitoring-Stack überwacht den Pi, alle Container und die Erreichbarkeit der Website von außen. Hohe Temperatur, Unterspannung, volle Platten, ausgefallene Container, fehlgeschlagene Deployments oder Backups meldet er sofort per Telegram.

🔥

METRIKEN

Prometheus

Sammelt alle Messwerte und wertet 24 Alarmregeln aus. Jede Regel hat Unit-Tests, die in der CI laufen.

📊

🔔

ALARME

CI/CD & GITOPS

Jede Änderung geprüft, automatisch ausgerollt.

Ich ändere nichts mehr von Hand auf dem Server. Jede Änderung landet als Pull Request im Repository, wird geprüft und erst nach dem Merge vom Pi selbst abgeholt.

01 GitHub Actions

Lint (ShellCheck, Ruff, Hadolint), Konfigurations-Checks, Alarm-Tests und ARM64-Image für die API

→
02 Deploy-Timer

Der Pi prüft alle 2 Minuten, ob es auf main einen neuen Commit mit grüner CI gibt, und holt ihn ab

→
03 Health-Check

Website und API werden geprüft. Bei einem Fehler rollt der Pi zurück und schlägt Alarm

✓
Pull statt Push

GitHub hat keinen Zugang zum Pi, und der Pi braucht keine offenen Ports. Dependabot hält Images und Pakete aktuell.

INFRASTRUKTUR ALS CODE

Der ganze Server in einem Playbook.

Die komplette Konfiguration des Pi ist mit Ansible beschrieben: Härtung, Firewall, Updates, Docker, die Anwendung, Secrets, Timer und die externe Platte. Ein frisch geflashter Pi wird mit einem Playbook wieder zum laufenden Server.

🛡️

HÄRTUNG

Abgesichert ab Werk

SSH nur mit Schlüssel, kein Root-Login. Die Firewall lässt eingehend nur SSH und VNC aus dem Heimnetz durch. Sicherheitsupdates laufen automatisch.

🔑

SECRETS

Ansible Vault

Tunnel-Token, Passwörter und Bot-Token liegen verschlüsselt im Repository. Die CI kennt das Vault-Passwort nie.

🚪

SICHERHEITSNETZ

Nie ausgesperrt

Ich habe keinen physischen Zugriff auf den Pi. Schlüsselprüfung, sshd-Validierung und ein Rettungs-Timer für die Firewall verhindern, dass ich mich aussperre.

🔁

ABGLEICH

changed=0

In der CI läuft das Playbook zweimal in einem Debian-Container, der zweite Lauf muss nichts ändern. Gegen den echten Pi meldet --check keine Abweichung.

ansible/roles/ 
base       Grundpakete, nicht benötigte Dienste (NFS) aus
ssh        sshd nur mit Schlüssel
firewall   ufw mit Rettungs-Timer
updates    unattended-upgrades
boot       Kernel-Parameter (z. B. Memory-Cgroup)
docker     Docker aus dem offiziellen Repository
storage    externe Platte (ext4) unter /mnt/data
app        Repository, Docker-Secrets, Deploy- und Metrik-Timer
backup     restic-Backup und Restore-Test

BACKUP & RESTORE

Nicht nur sichern. Auch wiederherstellen können.

Code und Konfiguration liegen in Git, die Secrets im Ansible Vault. Gesichert werden muss deshalb nur der Zustand: die Grafana-Datenbank, die Messwerte von Prometheus und die Einstellungen des Alertmanagers.

01 Täglich 03:00

Container kurz anhalten, Zustand mit restic sichern, alte Stände nach festen Regeln ausdünnen

→
02 Externe Platte

Verschlüsseltes, dedupliziertes restic-Repository auf der ext4-Platte außerhalb der SD-Karte

→
03 Restore-Test sonntags

Neuestes Backup in Wegwerf-Container ohne Netzwerk zurückspielen und die Daten darin prüfen

✓
Ernstfall geübt

Die Wiederherstellung wurde am laufenden Pi durchgespielt: Messwert-Historie vollständig, Website erreichbar. Schlägt ein Backup oder Restore-Test fehl, kommt ein Alarm.
